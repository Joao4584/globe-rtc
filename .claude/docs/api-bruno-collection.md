# Bruno collection for the API

The user keeps a Bruno collection of the HTTP API **outside the repo** (a local
`Globe-Rtc` folder in their Bruno workspace; OpenCollection YAML format, Bruno
3+). Request docs are in Portuguese, on purpose (user preference). It was
generated by a script, so after adding or changing routes in `apps/api`,
update the collection to match (the folders follow the controllers:
`00-autenticacao`, `01-usuario`, `02-salas`, `03-amigos`, `04-suporte`,
`05-uploads`, `06-skins`, `07-limpeza`).

## Getting a token without OAuth

- Login is GitHub/Google through NextAuth, but the API itself has three ways
  to get a JWT (`accessToken`, 24h, also set as the `meta-session` cookie):
  `POST /user/integration`, `POST /user/register`, `POST /user/login`.
- `POST /user/integration` creates the user if no one has that `github_id` /
  `google_id` (the `id` field of the body) and otherwise just logs in. It does
  **not** verify the provider, it trusts the body. The collection uses this for
  its one-click "Gerar token" with a test user; no OAuth involved. Because it
  trusts the body, the route is `@InternalOnly()`: in production it needs the
  `x-internal-key` header (a key derived from `NEXTAUTH_SECRET`), which the
  collection sends from the `internalApiKey` environment variable. See
  [internal-routes.md](./internal-routes.md). In development the header is
  optional, so `internalApiKey` stays empty.
- Each login stores `last_login_iat`, which invalidates the previous token of
  the same user (one active session per user). The collection therefore uses
  its own test users (`Bruno Teste`, `Bruno Senha`, `Bruno Amigo`) instead of
  the user's real account, so it does not log them out of the site.
- Real account: set `realIntegrationId`/`realEmail`/`realName` in the Local
  environment (github id from `https://api.github.com/users/<login>`), or copy
  the `meta-session` cookie from the browser into the `token` variable.

## How the collection is wired

- Environment `Local` (`baseUrl` = `http://localhost:4000`, test user data).
- Collection-level auth is `Bearer {{token}}`; every request inherits it
  (`auth: inherit`), including routes the API leaves public (skins, upload
  file/room image), because the user wants the header sent everywhere. Only
  the five token-generating requests (Gerar token, Cadastrar, Login, Entrar
  com conta real, Gerar token do usuário 2) have no auth. In Bruno, a request
  with no `auth` key means "No Auth".
- After-response scripts store variables for the next requests: `token`,
  `userPublicId`, `roomPublicId`, `privateRoomPublicId`, `roomAccessToken`,
  `token2`, `user2PublicId`, `friendshipPublicId`, `supportPublicId`,
  `uploadPublicId`, `uploadFileName`. They are runtime variables (memory
  only).
- Active query params are written both in the URL and in `params` (the Bruno
  CLI only reads the URL).
- Verified with the Bruno CLI (`@usebruno/cli`) against the running API: the
  whole collection passes, and `07-limpeza` removes the rooms it created.
  Users stay in the database.
- Every Nest `@Post()` without `@HttpCode` answers `201`, including login.
